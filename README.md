# P2P Minecraft (аналог Essential: хостинг мира без белого IP и VPS)

## Как это работает
1. Хост открывает свой одиночный мир и в меню паузы жмёт **P2P: Invite friends**. Мод публикует мир на локальный порт,
   узнаёт внешний адрес через публичный STUN и показывает **код-приглашение**.
2. Друг в меню **Мультиплеер** жмёт **P2P: Join** (кнопка слева вверху), вставляет код и нажимает **Connect**. Мод показывает **ответный код**.
3. **Автоприём:** хосту ничего вводить не нужно. Гость сам «стучится» к хосту с подписью из кода, хост принимает его и оба
   NAT «пробиваются» одновременно (UDP hole punching). Ответный код нужен только как запасной вариант, если у хоста строгий NAT
   и гость не смог подключиться сам: тогда гость отправляет ответный код хосту, хост вставляет его и жмёт Accept.
   Отключить автоприём (подтверждать каждого друга вручную): `"autoAccept": false` в `config/p2pmc.json`.
   Проверка лицензии: кнопка **Licence check** на экране хоста (или `"onlineMode": true` в `config/p2pmc.json`; по умолчанию включена) пускает только игроков с лицензией; `false` пускает и пиратские лаунчеры (имена не проверяются, держите код в секрете).
   Код-приглашение действует как пароль: любой, у кого он есть, может зайти, пока мир открыт.
4. Дальше игра идёт как по LAN, но через шифрованный прямой канал (X25519 + ChaCha20-Poly1305, ключ привязан к токену из кода).

Ни VPN, ни VPS, ни сторонних серверов, кроме публичных STUN (они только сообщают ваш внешний адрес, трафик игры через них не идёт).

## Если прямое соединение невозможно (CGNAT, симметричный NAT)
Нужен релей, и серверы тут не обойти (ZeroTier и Radmin делают так же). Запасной вариант: хост запускает playit.gg
на порт своего мира, друзья заходят на адрес playit как на обычный сервер. Мод показывает порт мира на экране хоста.

## Paper-плагин («P2P: Invite friends» для сервера на домашнем ПК)
Положите jar с `PLUGIN` в имени (из Releases) в `plugins/`. Команды (право `p2p.admin`, по умолчанию операторы):
- `/p2p invite` показывает код-приглашение (запускает хостинг при первом вызове)
- `/p2p accept <ответный код>` нужен только если друг не смог подключиться сам (автоприём включён по умолчанию: `auto-accept: true` в `config.yml`)
- `/p2p status` показывает сеть и друзей с пингом, `/p2p stop` останавливает
- `auto-start: true` в `plugins/P2PMinecraft/config.yml` печатает код в консоль при старте сервера

Важно: друзья заходят через 127.0.0.1, поэтому у всех один IP. В `bukkit.yml` поставьте `connection-throttle: 0`
(иначе двое друзей, зашедших в пределах 4 секунд, получат отказ) и оставьте `server-ip` пустым в `server.properties`.
Друзья подключаются модом (P2P: Join), как и к миру хоста.

## UPnP, QR-код, язык
- **UPnP:** хост просит роутер открыть UDP-порт (`"upnp": true` в `config/p2pmc.json`, `upnp: true` в конфиге плагина). Это помогает даже при строгом NAT. Если на роутере UPnP выключен, мод об этом напишет, а соединение пойдёт обычным путём. Порт закрывается при остановке хостинга.
- **QR-код:** на экране хоста кнопка **QR** показывает код-приглашение как QR, чтобы получить его на телефон камерой.
- **Язык:** мод сам выбирает русский, если в игре выбран русский язык, иначе английский. Для плагина: `language: ru` или `en` в `config.yml`.

## Discord-вебхук (оповещение «сервер включён» + код)
Когда хостинг стартует, мод/плагин может написать в Discord-канал, что сервер онлайн, и прислать код-приглашение.
Создайте вебхук: настройки канала, Интеграции, Вебхуки, Новый вебхук, Копировать URL.
- Мод: секция `discord` в `config/p2pmc.json` (`enabled`, `webhookUrl`, `username`, `serverName`, `mention`, `startMessage`, `notifyStop`, `stopMessage`).
- Плагин: секция `discord:` в `plugins/P2PMinecraft/config.yml`; `/p2p announce` отправляет код повторно.
- В сообщениях работают `{name}` и `{code}`; `mention` (например `@everyone`) пингует участников.
- URL вебхука секретный, а код работает как пароль: используйте приватный канал (при автоприёме любой, кто видит код, может зайти).
- Принимаются только https-адреса discord.com / discordapp.com.
- Если у вас уже есть старый конфиг, удалите его один раз, чтобы появились новые ключи (или добавьте их вручную).

## NeoForge (Minecraft 1.21.1, например ATM10)
Файл `MOD-neoforge-1.21.1-client-build*.jar` кладётся в `mods/` у каждого игрока (хост и гости; сборка модов должна совпадать).
Кнопки те же: «P2P: Invite friends» в меню паузы, «P2P: Join» в меню «Мультиплеер». Конфиг `config/p2pmc.json`.

## Структура
- `core/` чистая JDK (Java 21+): криптография, STUN, надёжный UDP (ARQ), коды-приглашения, мост TCP<->P2P. Без Minecraft и без зависимостей.
- `mod/` Fabric-мод (Minecraft 26.x, Java 25): экраны, кнопки (2 миксина), конфиг `config/p2pmc.json`.
- `neoforge/` порт мода на NeoForge 21.1.x (Minecraft 1.21.1, Java 21).
- `plugin/` Paper-плагин (тонкая обёртка над ядром).
- Готовые jar: на GitHub в разделе **Releases** (файл с `MOD` в имени для клиента, с `PLUGIN` для сервера).
- `.github/workflows/build.yml` собирает оба jar, гоняет тесты и публикует релиз.

## Проверка ядра (без Minecraft)
```
javac --release 21 -d out $(find core/src -name '*.java')
java -cp out dev.p2pmc.crypto.CryptoSelfTest
java -cp out dev.p2pmc.net.TransportSelfTest
java -cp out dev.p2pmc.net.EndToEndSelfTest
```

## Сборка мода и плагина
```
cd mod    && gradle build     # jar в mod/build/libs
cd plugin && gradle build     # jar в plugin/build/libs
```
Или без установки Java: загрузите папку в репозиторий GitHub, и workflow соберёт оба jar (артефакт `p2pmc-jars`).
Версии (`minecraft_version`, `loom_version`, `loader_version`) сверьте на https://fabricmc.net/develop.

## Статус
- Мод и плагин собираются против Minecraft / Paper 26.3 (GitHub Actions) и работают в игре.
- Протестировано в игре: хост и гость в одной локальной сети. Соединение через интернет зависит от NAT обеих сторон
  (см. раздел про CGNAT выше); при неудаче используйте запасной туннель (playit.gg).

## Как проверить соединение через интернет
1. Хост открывает мир и копирует код. В коде должен быть публичный адрес (не только 192.168.x.x).
2. Гость находится в другой сети (другой Wi-Fi, мобильный интернет, друг в другом городе), вставляет код и жмёт Connect.
3. Хосту вводить ничего не нужно: гость подключается сам, на экране видно состояние и пинг. Если за несколько секунд не
   подключилось, гость отправляет хосту ответный код, хост вставляет его и жмёт Accept.
   Если и так зависает, хотя бы одна сторона за симметричным NAT/CGNAT.
